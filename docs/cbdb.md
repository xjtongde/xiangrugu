本文件记录从 `usedata` 源件直接观察到、会影响忠实读取或后续解释的事实。它不是导入合同，不为源数据判错，也不以现有 PostgreSQL `cbdb` 为依据。

## 结构要点

2026-10-09已按单件项目快照重新建立完整结构证据，78表/736字段/76个主键自动索引，
无视图、触发器或显式外键；最新口径与非执行逻辑对象提案统一见
[sqlite-review.md](../datamgmt/contracts/releases/2026-10-06-bootstrap/sqlite-review.md)。
随后完成指定三表28列类型统计，最新结果与空表限制也见该审阅页；
本节及下列G4历史观察不构成完整值合同或独立数据库验收。

- 源 SQLite 当前枚举为 78 表；正式数量以阶段 0 重跑证据为准；
- 源中没有显式外键约束，显式业务索引也不能假定存在；目标库索引属于性能层，不能改变保真数据；
- 常见易错列名：坐标为 `x_coord/y_coord`，亲缘对端为 `c_kin_id`，`NIAN_HAO` 名称为 `c_nianhao_chn`；
- 未知值可能以 `NULL`、`0`、负数或其他哨兵表达，不得在导入时统一清洗；
- 不同来源或版本可能采用不同记录粒度，不能用另一版本的行数作为本源件真值。

## G4 语义哨兵摘要

以下编号用于证明导入后仍保留源件中已观察到的形状和值。精确 SQL 与期望值当前保存在 `datamgmt/config/g4_assertions.yaml`，但该配置仍使用旧目标命名，须在阶段 0 按新合同重建后才可执行。

| 编号 | 源位置 | 必须保留/复核的现象 |
|---|---|---|
| G4-01 | `ASSOC_DATA.c_assoc_first_year` | `-1`、`0`、`-9999` 等哨兵并存 |
| G4-02 | `BIOG_MAIN.c_birthyear` | `NULL`、0、负数及异常大值并存 |
| G4-03 | `BIOG_MAIN.c_index_year` | 边界外年份和异常大值存在 |
| G4-04 | `POSTED_TO_OFFICE_DATA.c_firstyear` | 0、NULL 和少量负值并存 |
| G4-05 | `POSTED_TO_ADDR_DATA.c_addr_id` | 0 有源内语义，不能自动转 NULL 或删除 |
| G4-06 | `ADDR_CODES` | 坐标覆盖不完整，且存在已记录的离群坐标 |
| G4-07 | 参考关系 | 源无 FK；部分数据集存在源内悬空引用 |
| G4-08 | `BIOG_MAIN.c_name_chn` | 人名不唯一，不能作为实体主键 |

## 使用规则

1. 哨兵只验证“数据库是否忠实保留源观察”，不判断源值是否正确；
2. 任何计数在源版本变化后都必须从源字节重算；
3. G4 不代替结构、数量和值全等闸门，也不能把抽样观察推广为全库结论；
4. 如人读摘要与机器证据不一致，先停止执行并重跑源侧读取，不得拿旧 `cbdb` 裁决。
