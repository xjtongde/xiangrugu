## 2. 方案选择与旧路径边界

选用类型标记和长度前缀二进制表达，字段边界独立于业务字符，UTF-8及整数表达唯一。

带类型标签的JSON也能正确区分NULL和空串，但需要额外固定转义、数字及序列化规则；本切片不采用。继续使用普通字符串哨兵/分隔符则存在实际字符碰撞，拒绝。

旧 `truth/read_text.py:read_tsv`会把空字段转None、补裁宽度并嗅探类型；旧 `verifier/verify.py:_canon_typed`将None与真实U+2400混同。这些路径不得成为本切片源真值、规范表达或比较器，不在本批顺手改写旧代码。原含表头的有序JSON摘要只保留为历史辅助证据，不迁作本格式摘要。

## 3. 输入与独立性

未来纯比较模块接收对象描述、完整列描述和两条独立typed-row迭代器，不连接数据库、不扫描文件、不推断schema/表名或类型。内部不得调用importer。

源侧独立适配器从只读、已验证快照及精确获批读取规则直接读取源字节，排除头部，将数据记录按原顺序从1编号。库侧适配器读取实际目标列类型、列顺序、nullable及原生text/int/None值，不先用SQL文本化或COALESCE将NULL替换为字符哨兵；结构通过后才比较值。它们只能共享本规格的纯值序列化器，不能共享装载器解析结果、中间文件或源期望。

已批准独立 `source_text` 字节读取器可作为未来源侧路径；若这样使用，未来加载器必须选择另一条分列实现，不能双方同时复用source_text。本规格只定义接口边界，不宣称加载器或库侧适配器已实现。真实源预期必须在另获授权后重新从独立源路径生成并绑定快照证明，不能从旧库或目标输出倒推。

列结构包括：顺序、column_key、target_name、type、nullable。源列column_key为既有column_id；派生行号固定key `derived:__src_rownum`，置于全部源列之后，type=bigint，值必须为一基数据记录序号。源列类型/nullable直接取已批准映射，不允许另推数字或缺失语义。

五件源列均nullable=false；NULL编码只供通用接口及显式nullable=true的合成测试使用，不授权五件源列存NULL。行号非NULL和连续唯一是派生序号的验证语义，不额外批准数据库主键或UNIQUE约束。

## 4. 严格值编码

所有长度单位为字节；多字节整数统一大端。u32/u64为无符号4/8字节，i64为有符号8字节二补码。数值超界必须拒绝，不截断或溢出。

| 值 | 完整单元格字节 |
|---|---|
| NULL | `00`，无payload；仅nullable=true允许 |
| text | `01` + u64(UTF-8字节数) + 严格UTF-8字节 |
| bigint | `02` + i64(value) |

text输入必须是str，不做NFC/NFKC、strip、大小写折叠、替换字符、日期/数字/哨兵解释或str强制转换。空串是 `01` 后接八个零字节；真实U+2400是长度3的text，不是NULL。`U+0000`、引号、TAB、LF及CR作为字符在纯编码中原样保留；孤立surrogate无法严格UTF-8编码时拒绝。若某载体/目标无法表示某字符，适配器必须另报不支持并阻断，不能以编码器支持为目标可装载证明。

bigint只接受原生int且排除bool；范围为-2^63至2^63-1。不接受float、Decimal或数字字符串，不归约、舍入或自动转型。错误保留对象/行/列身份及类型，不输出业务值。

黄金单元格向量必须手工固定：NULL=`00`；空串=`01 0000000000000000`；`␀`=`01 0000000000000003 e29080`；整数1=`02 0000000000000001`；整数-1=`02 ffffffffffffffff`。这些向量不是来自待测编码器生成的答案。

## 5. 列描述、行和完整对象摘要

列描述采用JSON数组，每项为 `[column_key,target_name,type,nullable]`，保持合同列顺序。序列化固定为Python JSON语义：ensure_ascii=true、allow_nan=false、separators=(',',':')，无缩进、无尾LF，编码ASCII；字段只允许已验证的字符串/布尔，不含字典、浮点或隐式默认值。该表达用于结构绑定，不把序列化后的转义字符串当业务值。schema_hash为上述完整列描述字节的SHA-256。

对象流格式固定为：

```text
header = ASCII "XRGVALUE" + 00 + 01
       + source_object_id的32个原始摘要字节 + schema_hash的32个原始摘要字节
row    = 52 + u32(列数) + u64(payload长度) + payload
payload= 按合同列顺序拼接的全部完整单元格编码（含最后的派生行号）
trailer= 45 + u64(完整数据记录数)
stream = header + row[1] + ... + row[N] + trailer
```

00/01/52/45在此分别指单字节十六进制值，不是ASCII数字。source_object_id须是已验证的64位小写十六进制身份。空表仍具有完整header和count=0的trailer。摘要为完整stream的SHA-256；与历史含表头JSON摘要是不同格式，不得比较或混标版本。数据库/schema/表名不入值流，避免位置或未冻结表名改变值定义；目标位置必须在G2/证据中另行核验，不能靠值摘要证明归属。

目标端先按派生行号的数值顺序输出，再验证行号恰为1..N；不能依赖物理返回顺序或字符串排序。源端不得重排。重复的业务值行全部保留；重复/缺失/越界行号、头部混入、列宽不同及多件对象混流均失败。任一端中途失败、截断或超预算时不返回完整摘要或通过结论；报告只允许前缀处理计数并明确partial=true。

## 6. 比较与证据

比较器先验证两端结构与获批描述完全一致，包括列集合、顺序、名称、类型及nullable；随后在一次流式遍历中验证序号并逐值比较，到两端正常结束后才确认完整计数。两端按序逐行逐列比较类型和完整payload字节，不能只比SHA-256，不能因摘要相同跳过逐值比较。没有主键的业务重复行由保留序号对齐，本切片不做业务去重；其他无序载体仍须实现DESIGN的分区/字节/重复次数比较。

错值、错类型、错空串/NULL、Unicode码点变化、漏列、漏行、多行和顺序变化均失败。比较器可以共享无损字节编码函数，但黄金向量及至少一条独立参考编码验证其正确性；注入摘要碰撞返回值后，真实字节差异仍须被检出。

机器报告至少包含format_version、source_object_id、schema_hash、输入证据引用及SHA-256、源/目标完整或partial计数、完整摘要（仅整件成功可有）、比较字段数、总差异数、差异列表、列表是否截断、资源预算和结果。默认差异列表最多100项，仅记录行号、column_key、预期/实际类型、字节长度及辅助摘要，不打印值、SQL连接参数或其他秘密。达到列表上限仍继续检查完整输入并累计总差异，预算不足则整体失败，不能报告全部已验证。

纯合成比较结果只能标为comparison_equal或comparison_failed；没有真实源、目标及G0–G7证据不得标CONFORMS或生成数据库验收证书。

## 7. 资源和拒绝规则

第一切片显式默认预算：100,000数据记录/端、512列（含派生列）、单text字段UTF-8不超过1MiB、单行payload不超过8MiB、完整规范流每端不超过256MiB、差异明细最多100项。调用者可以收紧，不能静默扩大；未来扩大须声明运行预算，不更改v1字节格式。

编码前检查类型/整数范围/列数；字符串字符数可先作低成本上界拦截，再严格编码并检查字节预算。行payload必须在字段预算及累计流预算内受控构造，不能按不可信长度预分配巨块。逐行比较只保留当前两行及有界差异明细，不将整件流存入内存。读完整输入、验证完成后才返回完整摘要；取消、超时、迭代器抛错或资源耗尽都明确失败，无成功前缀证书。

未知格式版本、未知类型、非法nullable、重复column_key/target_name、列宽不符、非法对象身份、整数越界、隐式类型转换、非法UTF-8及预算超限都拒绝，不尝试宽松回退。
